### Your question:

> **“In this code, how did he take out `addToCart.actions`? Where is he pointing to the reducer, as `action` is under `reducers`?”**

You're **right on spot**. The confusing part is that `createSlice()` automatically creates an `actions` object **from the reducers you define**.

Let's break it down simply.

### 1. Your code

```js
const addToCart = createSlice({
    name: 'cart',
    initialState,
    reducers: {
        addItem: (state) => {
            state.value += 1;
        }
    }
});
```

You wrote:

```js
reducers: {
    addItem: (state) => {
        state.value += 1;
    }
}
```

Here, `addItem` is a **reducer function**.

But Redux Toolkit automatically generates an **action creator** for every reducer you put inside `reducers`.

So internally, conceptually, you can think of it as:

```js
addToCart = {
    name: 'cart',

    reducer: function(...) {
        ...
    },

    actions: {
        addItem: function(...) {
            ...
        }
    }
}
```

So:

```js
addToCart.actions
```

gives you:

```js
{
    addItem: ...
}
```

And therefore:

```js
const { addItem } = addToCart.actions;
```

extracts that generated action creator.

---

### 2. Why does `actions` exist when we only wrote `reducers`?

This is the important point.

You **don't manually create**:

```js
actions: {
    addItem: ...
}
```

`createSlice()` does it for you.

You provide:

```js
reducers: {
    addItem: (state) => {
        state.value += 1;
    }
}
```

Redux Toolkit says:

> "Okay, you have a reducer called `addItem`. I'll automatically create an action creator called `addItem` for you."

So:

```text
                    createSlice()
                         |
                         |
              ---------------------
              |                   |
          reducers             actions
              |                   |
          addItem()           addItem()
              |                   |
       actual state          action creator
        modification
```

---

### 3. What does this line do?

```js
export const { addItem } = addToCart.actions;
```

It is simply **destructuring**.

First:

```js
addToCart.actions
```

returns something conceptually like:

```js
{
    addItem: function
}
```

Then:

```js
const { addItem } = addToCart.actions;
```

means:

```js
const addItem = addToCart.actions.addItem;
```

So you are extracting the generated action creator.

---

### 4. But then where is the actual reducer?

The reducer you wrote:

```js
addItem: (state) => {
    state.value += 1;
}
```

is used by Redux Toolkit to handle the action.

For example, when you do:

```js
dispatch(addItem());
```

the flow is:

```text
dispatch(addItem())
       ↓
action creator creates:
{ type: "cart/addItem" }
       ↓
Redux receives action
       ↓
cart reducer sees "cart/addItem"
       ↓
runs:
(state) => {
    state.value += 1;
}
       ↓
state.value increases
```

### The key distinction

Don't think:

```text
reducers → actions
```

as if `actions` is a property inside your `reducers` object.

Instead think:

```text
createSlice()
    |
    +── reducers: You provide these
    |       |
    |       +── addItem: reducer function
    |
    +── actions: Redux Toolkit generates these
            |
            +── addItem: action creator
```

So **`addToCart.actions` is a property generated by `createSlice()`**, based on the reducer names you provided.

### One-line memory trick

> **You write the reducer; `createSlice()` automatically creates the corresponding action creator.**

And that's why this works:

```js
export const { addItem } = addToCart.actions;
```

Here `addItem` is **not the reducer function directly** — it is the **action creator generated from the reducer named `addItem`**.
